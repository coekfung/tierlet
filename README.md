# Tierlet

Tierlet is a native macOS client for [EasyTier](https://github.com/EasyTier/EasyTier).

It provides a SwiftUI interface and runs EasyTier through a one-time authorized privileged service. This preserves the standard TUN mode while avoiding repeated authentication prompts.

## Goals

- Provide a native macOS experience
- Manage multiple EasyTier networks
- Use standard TUN mode without Network Extension
- Require authorization only during initial setup
- Keep common settings simple while retaining full configuration flexibility

## Architecture

Tierlet consists of three main components:

- `Tierlet.app`: The SwiftUI frontend for network lists, details, and configuration
- `tierletd`: A privileged LaunchDaemon responsible for configuration storage and network lifecycle
- `tierlet-core`: A Rust bridge around EasyTier's multi-instance runtime

The app communicates with the privileged service through a code-signing-validated XPC interface. The EasyTier core does not expose an additional local management port.

Service code is grouped under `TierletService/`: `Contract/` contains the XPC
contract shared by the app and daemon, while `Core/` contains the Rust engine
and its daemon-only UniFFI bridge.

Tierlet targets macOS 13 or later and supports both Apple Silicon and Intel Macs.

## Network Management

The home screen presents networks as cards. Each network can be started, stopped, and configured independently.

Network details include runtime status, peers, routes, and logs.

Enabled networks connect when Tierlet starts, never before user login. Quitting Tierlet normally disconnects all active networks.

## Configuration

The basic configuration editor covers common settings such as:

- Network name and secret
- Hostname
- Static IPv4 or DHCP
- Initial peers

Advanced settings are provided through a TOML editor. Advanced TOML values override matching fields generated by the basic editor. The final configuration is validated using EasyTier's own configuration parser.

Each network has a stable profile ID mapped to a stable EasyTier instance.

## Privileged helper signing

The app validates the daemon's signing identifier and Team ID, and the daemon
validates the app's signing identifier and Team ID. `tierletd` is a command-line
tool, so its identifier is explicitly set to
`wang.coekfung.tierlet.daemon` while signing; do not remove that build setting.

After producing a Developer ID-signed and notarized build, verify both
acceptance and rejection paths before installing it:

```sh
Scripts/verify-xpc-signing.sh /path/to/Tierlet.app
```

When either the helper executable or its plist changes, use **Uninstall Helper**
and then **Install Helper** from the app. Approve the new helper in System
Settings if macOS requests it.

## Development

Requirements:

- macOS 13+ with Xcode
- An Apple Developer Program team with a valid Developer ID Application certificate to test the privileged LaunchDaemon; the app bundle must be notarized before `SMAppService` can install it
- Rust stable toolchain with the `aarch64-apple-darwin` and `x86_64-apple-darwin` targets (`make bootstrap` adds them via rustup)
- `protoc`, the protobuf compiler, on `PATH` (`brew install protobuf`), required by EasyTier's build

Commands:

- `make check` — Rust formatting, clippy, and plist linting
- `make test` — Rust unit tests and a Debug build
- `make build-universal` — universal (arm64 + x86_64) Release build
- `make ci` — everything CI runs

Xcode invokes `TierletService/Core/Makefile` before compiling `tierletd`. The
UniFFI Swift bindings are regenerated at `TierletService/Core/Generated/`; do
not edit them directly.
